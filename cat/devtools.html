这个分类里怎么挑

选站标准

开发工具栏只收开发者日常真正会打开的站点：代码托管、包管理器、技术问答社区、官方文档、部署与云服务、容器镜像仓库。排除的是：内容农场式的「XX 教程」站、已经停止维护的项目（GitHub 超过两年无提交且无版本发布的）、以及单纯的学习路线图仓库。判断标准是「它是否在生产环境里被使用过」。

使用建议

先看你要解决的是哪一类问题。写代码：代码托管 + 本地环境管理；查问题：技术问答社区（能搜到历史解决方案的优先）；看文档：优先官方文档站，MDN 与各语言官方站是首选；上线：部署平台与云服务；装依赖：包管理仓库。遇到报错时的顺序通常是：官方文档 → 问答社区 → 源码仓库的 issue，这条路径在本栏的排序里也体现了出来。

按需求快速定位

  • 代码托管与协作 → GitHub、GitLab
  • 查报错与历史解法 → Stack Overflow、Qiita、Zenn、velog
  • 查 API 与标准实现 → MDN Web Docs（以官方文档为准）
  • 部署与云服务 → Vercel、Cloudflare、DigitalOcean、阿里云、腾讯云
  • 找包与镜像 → npm、PyPI、Docker Hub

常见误区

三个常见坑：把博客当文档——CSDN、掘金的文章时效性差，版本一升级就失效，配置与 API 一律回到 MDN 或官方文档；忽略网络可达性——npm、PyPI、Docker Hub 在国内直连常超时，配好镜像源能省掉大量排查时间；选云服务只看价格——Vercel、Cloudflare 的免费额度适合静态站与边缘函数，长驻进程、数据库和固定 IP 还是得 DigitalOcean、阿里云这类。

补充说明

本站本身也是纯静态部署在 Cloudflare Pages 上，这栏里的许多工具在同类方案中被反复比较过。一点实践经验：选托管平台时优先看「出问题后能不能自己捞数据」，而不是只看部署速度；选包仓库时注意许可证与依赖审计能力，这两点在后期出问题时的影响远大于日常便利性。
